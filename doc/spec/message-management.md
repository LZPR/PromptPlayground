# 消息管理规格

## 单条消息操作

所有操作默认作用于所选消息节点；除“发送”“重新生成”和空分支的“继续生成”外，不发起模型请求。消息编辑界面、状态兼容的操作入口和生成期间禁用规则以 [聊天界面](chat-ui.md) 与 [交互规格](interaction.md) 为准。

| 操作 | 行为 |
| --- | --- |
| 插入 | 可在消息前或后插入空消息。打开统一底部消息编辑器，Role 必选，默认 `system`。 |
| 添加 | 可在当前路径最开始或最末尾新增消息。最开始默认 `system`，最末尾默认 `user`；随后可在编辑器修改 Role 和文本。空分支中在末尾添加首条消息会使其实体化。 |
| 修改 | 使用统一底部消息编辑器修改文本和 Role，并提供默认勾选的“创建新分支”选项。 |
| 删除 | 可标记为待删除，或永久删除。待删除消息可恢复；永久删除遵循下游重连规则。 |
| 分支 | 从当前消息创建持久化空后继分支，并立即切换到该分支。 |
| 复制 | 将该消息的完整内容复制到系统剪贴板。 |

### 修改的分支语义

- 勾选“创建新分支”时，新路径共享被修改消息之前的上游节点，并以修改后的消息替换该位置；原消息及其后续路径保留不变。
- 未勾选时，直接更新原节点。该节点被多个路径共享时，所有下游分支都看到修改后的内容。

### 删除与恢复

- 待删除不会改变树边，仅改变消息状态。恢复后，消息回到正常状态与原位置。
- 永久删除移除节点，并将所有直接子节点连接到被删除节点的父节点；若父节点为虚拟根，子节点直接成为虚拟根的子节点。
- 删除前应明确告知用户永久删除会影响下游连接；批量删除不执行永久删除。

## 排序模式

- 排序是独立全局模式，与批量选择模式互斥。
- 排序范围限定为分支节点之间的同一线性消息段。排序模式只允许交换该线性段内的正常和待删除非分支消息。
- 分支节点及其全部子树不可拖动，也不能作为拖放目标。消息不可跨越分支节点排序，不可改变消息的父子分支归属。
- 任何会造成跨分支共享下游、循环或其他无效树结构的拖放目标均显示禁用视觉提示，并阻止放置。

## 批量选择模式

- 批量选择是独立全局模式，与排序模式互斥，支持跨分支多选。
- 支持逐条选择、按 Role 筛选，以及从所点消息向其所在根到叶路径选择之前或之后的全部消息；范围选择不会扩展到其他分支。
- 可折叠显示已选消息内容。折叠只改变展示密度，不改变选择、消息状态或请求内容。
- 批量删除统一将所选消息标记为待删除；不提供批量永久删除。已待删除消息可被选择，但不作为筛选后的默认目标。
