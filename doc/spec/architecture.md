# 技术架构与选型

## 平台与运行时

- 应用运行时采用 **Tauri 2**。
- 首版目标平台为 Windows 和 Android，核心会话、消息、分支、设置和模型调用功能保持对等。
- 前端以单页应用方式运行，不使用 SSR、Nuxt 或云端后端。
- 应用保持单用户、本地优先、无账户、无云同步和无多人协作。

## 前端

- 使用 Vue 3、TypeScript 和 Vite。
- 使用 Pinia 管理会话列表、消息树、当前分支、生成状态和全局偏好。
- 使用 Vue Router 管理聊天、会话管理、分支管理和设置等视图；窄屏布局切换视图时必须保留当前会话、分支和编辑状态。
- 使用 Element Plus 提供基础表单、按钮、菜单、对话框和反馈组件。
- 消息气泡、分支分隔符、消息树节点和聊天底栏等产品核心界面由项目自定义实现，不直接套用组件库的展示组件。

### 大内容渲染

- 消息列表和分支树采用虚拟化渲染，不能因为完整上下文较大而一次性渲染所有消息内容。
- Markdown 渲染使用 `markdown-it`，禁用内嵌 HTML。
- Markdown 输出经过 DOMPurify 清理；外部链接按聊天界面规格在新窗口打开，并设置安全的链接属性。
- Raw 模式显示原始文本，Markdown 模式只改变显示层，不改变持久化文本和模型请求内容。

## 本地存储

- 持久化数据库采用 SQLite。
- Windows 和 Android 均通过 Tauri 官方 SQL 插件访问 SQLite，数据文件位于应用配置目录。
- 数据访问采用 `tauri-plugin-sql` 加参数化 SQL，不引入 ORM。
- 数据库迁移由 Rust 侧注册和管理；每次迁移必须具备唯一版本，并在事务中执行。
- SQLite 至少保存以下数据：
  - 会话元数据，包括标题、创建时间、更新时间和当前分支定位。
  - 消息节点，包括父节点、Role、文本、消息状态和创建顺序。
  - 全局显示偏好和模型设置。
  - 原型阶段的 API Key。
- 临时错误记录不进入 SQLite。

前端通过以下数据访问边界使用持久化数据，业务组件不得散落 SQL：

- `SessionRepository`：会话创建、重命名、克隆、删除和列表查询。
- `MessageRepository`：消息树变更、当前路径查询、分支操作和批量操作。
- `SettingsRepository`：全局偏好、模型配置和 API Key 的保存、读取与清除。

API Key 的存取通过 `SecretStore` 抽象隔离。原型阶段使用普通本地存储，不能把该方案视为生产级密钥保护；后续可替换为 Windows Credential Manager、Android Keystore 或 Tauri Stronghold，而不改变业务层接口和其他数据结构。

## 模型请求

- OpenAI Chat Completions 兼容接口由 Rust 网络层统一访问。
- 网络层使用 `reqwest`，由 Tauri Commands 暴露给前端。
- Rust 层负责 API Key 注入、请求超时、请求取消、HTTP 错误映射和 SSE/流式响应解析。
- 流式响应通过 Tauri 事件发送增量内容、完成、失败和取消状态；前端不直接依赖 WebView 的 CORS、代理或流式实现。
- 每个会话最多同时存在一个活动模型请求。

## 测试工具链

- 使用 Vitest 测试消息树领域逻辑、Pinia 状态、Repository 映射和设置持久化。
- 使用 Rust 单元测试覆盖 SSE 分块解析、请求取消、超时和错误码映射。
- 使用 Playwright 覆盖会话切换、消息编辑、分支导航、Raw/Markdown 切换、窄屏布局和生成状态。
- Windows 和 Android 验收必须覆盖数据库迁移、数据恢复、API 请求、流式响应、取消请求和应用重启恢复。

## 性能假设

以下内容仅用于性能评估和实现设计，不代表项目实际做法，也不自动构成功能限制或验收指标：

- 一次请求的消息最大约 1M 上下文。
- 最小消息长度为 10 个字符。
- 每个消息节点的直接分支数不超过 10。
- 本地会话数量为百至千级。
